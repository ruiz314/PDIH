Para esta tarea se ha empleado el clasificador frontal avanzado \texttt{haarcascade\_frontalface\_alt.xml}. También importo la librería \texttt{sys} para poder incluir la imagen con la que se trabaja como parámetro en la orden de ejecución. Esto facilita probar con varias imágenes sin tener que tocar el fichero de código fuente. Además, uso la librería \texttt{os} para guardar las imágenes resultantes (con caras recuadradas) en la carpeta de trabajo.

\begin{lstlisting}[style=pythonstyle, caption={Librerías para el Ejercicio 1}, label={lst:lib1}]
import cv2
import sys
import os
\end{lstlisting}

Como la imagen con la que se va a trabajar se pasa por parámetro hay que comprobar que se haya pasado, que la ruta exista y que no esté corrupta:
\begin{lstlisting}[style=pythonstyle, caption={Comprobación de parametro}, label={lst:param1}]
# Validación del número de argumentos en la línea de comandos
if len(sys.argv) < 2:
    print("[ERROR] Uso correcto: python ejercicio1.py <nombre_imagen.jpg>")
    sys.exit(1)

# Captura del parámetro del archivo de imagen
nombre_imagen = sys.argv[1]

#Cargamos nuestro modelo classificador de Haar:
modelo = cv2.CascadeClassifier('haarcascade_frontalface_alt.xml')
  
#Cargamos la imagen
img = cv2.imread(nombre_imagen)

# Control de excepciones ante rutas inexistentes o corruptas
if img is None:
    print(f"[ERROR] No se pudo cargar la imagen '{nombre_imagen}'")
    sys.exit(1)    
\end{lstlisting}

A continuación, el programa sigue como el del ejemplo, haciendo el procesamiento de escala de grises, buscando rostros y dibujando los rectángulos sobre la imagen original. Una vez hecho eso, se guarda la imagen en disco separando el nombre de la imagen de la extensión:
\begin{lstlisting}[style=pythonstyle, caption={Guardar imagen}, label={lst:guardarimg1}]
# Separamos el nombre del archivo de su extensión (ej: 'foto' y '.jpg')
nombre_base, extension = os.path.splitext(nombre_imagen)

# Creamos el nuevo nombre para el archivo de salida
nombre_salida = f"resultado_{nombre_base}{extension}"

# Guardamos la imagen modificada en la carpeta de trabajo
cv2.imwrite(nombre_salida, img)
print(f"[INFO] Imagen resultante guardada con éxito como: {nombre_salida}")
\end{lstlisting}

\subsection{Ejercicio 2}\label{subsec:ejer2}
Para resolver este ejercicio se necesitan las mismas librerías que en el primer ejercicio (Ver Listing \ref{lst:lib1}). Al igual que en el primer ejercicio, el script empieza comprobando los argumentos de la terminal al ejecutar el programa. Al exigir la sintaxis \texttt{python ejercicio2.py <video>}, se hace más dinámica la prueba del programa con distintos videos sin tener que modificar código.


Antes de procesar la señal de vídeo se estructura el archivo de salida. Mediante el método \texttt{camara.get()}, el sistema consulta los descriptores de la cabecera del archivo multimedia para extraer tres variables clave: la tasa de refresco (\texttt{CAP\_PROP\_FPS}) y las dimensiones de los cuadros (\texttt{WIDTH} y \texttt{HEIGHT}). Se añade además una estructura condicional que actúa como salvaguarda fijando un muestreo estándar de $30$ FPS en caso de que el archivo de origen posea un \textit{framerate} variable no detectable.

\begin{lstlisting}[style=pythonstyle, caption={Extracción de propiedades del video}, label={lst:propiedadesvid}]
# Extrae las propiedades nativas del vídeo original
fps_leido = int(camara.get(cv2.CAP_PROP_FPS))      # Cuadros por segundo
ancho = int(camara.get(cv2.CAP_PROP_FRAME_WIDTH))  # Resolución: Ancho en píxeles
alto = int(camara.get(cv2.CAP_PROP_FRAME_HEIGHT))  # Resolución: Alto en píxeles

# Control de seguridad.
fps = int(fps_leido) if fps_leido > 0 else 30
\end{lstlisting}

A diferencia de trabajar con imágenes, donde no es necesario conocer las propiedades del archivo para usar la función \texttt{cv2.imshow()}, para trabajar con \texttt{cv2.VideoWriter} se necesitan saber los metadatos (\texttt{CAP\_PROP\_FPS}, \texttt{FRAME\_WIDTH} y \texttt{FRAME\_HEIGHT}) para que el archivo final se reproduzca a la misma velocidad que el original.


Para evitar fallos a la hora de almacenar el video resultante en disco no se usan rutas relativas. Con el módulo \texttt{os} se determina la ubicación física exacta del script en el disco duro y se aísla el nombre puro del fichero multimedia.

\begin{lstlisting}[style=pythonstyle, caption={Ruta de guardado}, label={lst:ruta}]
# Obtiene la ruta absoluta de la carpeta donde se está ejecutando el script
directorio_actual = os.path.dirname(os.path.abspath(__file__))

# Extrae solo el nombre del archivo de vídeo (eliminando rutas previas si las hay)
nombre_archivo_puro = os.path.basename(nombre_video)
nombre_base, _ = os.path.splitext(nombre_archivo_puro)

# Combinamos todo en una ruta absoluta limpia para Windows
video_salida = os.path.join(directorio_actual, f"resultado_{nombre_base}.avi") # Guarda en formato AVI para máxima compatibilidad con códecs en Windows
\end{lstlisting}

Se usa el códec \texttt{XVID} empaquetado bajo un contenedor binario de extensión \texttt{.avi}, asegurando compatibilidad con mi ordenador.

\begin{lstlisting}[style=pythonstyle, caption={Códec y extensión}, label={lst:extension}]
# Definir el códec de compresión de vídeo.
fourcc = cv2.VideoWriter_fourcc(*'XVID')

# Instanciar el objeto grabador con la ruta, el códec, los FPS y el tamaño de los fotogramas
grabador = cv2.VideoWriter(video_salida, fourcc, fps, (ancho, alto), isColor=True)

# Validar que el grabador se haya inicializado correctamente en el sistema operativo
if not grabador.isOpened():
    print("[ERROR] No se pudo inicializar el grabador de vídeo. Revisa los permisos de la carpeta.")
    sys.exit(1)
\end{lstlisting}

Dentro del bucle principal de ejecución, el proceso se divide en tres fases por cada \textit{frame} capturado:
\begin{itemize}
        \item Se transforma el plano de color empleando \texttt{cv2.COLOR\_BGR2GRAY} como se hacía en el tratamiento de imágenes.
        \item Se establecen los valores de \texttt{scaleFactor} y \texttt{minNeighbors}  para la función \texttt{detectMultiScale}.
        \item Se pintan los rectángulos sobre la matriz original a color (\texttt{img}) para no degradar la calidad estética del vídeo final. Acto seguido, se efectúa un volcado físico directo al disco mediante \texttt{grabador.write()} y, de forma paralela, se proyecta la imagen en la interfaz gráfica del usuario (\texttt{cv2.imshow()}).
\end{itemize}

\begin{lstlisting}[style=pythonstyle, caption={Frame a frame en ejercicio2}, label={lst:logica2}]
#Procesamiento frame a frame del vídeo
while camara.isOpened():
    hay_frame, img = camara.read()

    # Si 'hay_frame' es False, significa que el vídeo ha llegado a su fin
    if not hay_frame:
        print("Fin del archivo de vídeo alcanzado.")
        break

    # Convertir el frame a escala de grises para el algoritmo de Viola-Jones
    gris = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

    # Detectar rostros en el fotograma actual
    faces = modeloCara.detectMultiScale(gris, scaleFactor=1.3, minNeighbors=4)

    # Iterar sobre cada rostro detectado en el fotograma actual
    for (x, y, w, h) in faces:
        # Dibujamos el rectángulo delimitador sobre el frame original a color (img)
        # Color: Azul (255, 0, 0) en formato BGR. 
        # Grosor de línea: 3 píxeles
        cv2.rectangle(img, (x, y), (x + w, y + h), (255, 0, 0), 3)

    # Escribir el fotograma modificado (con rectángulos ya pintados) en el archivo de salida
    grabador.write(img)

    # Desplegar el frame en tiempo real en una ventana interactiva de Windows
    cv2.imshow('Ejercicio 2 - Detección Facial en Vídeo', img)
\end{lstlisting}

Con la función \texttt{waitKey} se captura si hay una pulsación de tecla. Si la tecla pulsada es la que corresponde con el número $27$ en ASCII, es decir, la tecla \texttt{Escape} (\texttt{Esc}), se fuerza la salida del bucle.
\begin{lstlisting}[style=pythonstyle, caption={Cerrar ventana}, label={lst:cierre2}]
while camara.isOpened():
    ...
    # Escuchar los eventos del teclado durante 1 milisegundo
    key = cv2.waitKey(1)
    # 27 es el código ASCII para la tecla 'Esc' (Escape)
    if key == 27:
        print("Proceso interrumpido manualmente por el usuario.")
        break
\end{lstlisting}

Una vez que se ha salido del bucle \texttt{while} se realiza el vaciado de búfer. 
\begin{lstlisting}[style=pythonstyle, caption={Limpmieza del búfer}, label={lst:bufer2}]
# Liberar los descriptores para que Windows cierre correctamente los archivos de video
camara.release()
grabador.release()  # Al liberar el grabador se finaliza la escritura física del archivo nuevo
cv2.destroyAllWindows()
print(f"[ÉXITO] Archivo de vídeo exportado correctamente en la raíz del proyecto.\n")
\end{lstlisting}
